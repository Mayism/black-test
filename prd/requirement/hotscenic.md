# 热门景点产品需求文档

## 1. 需求概述

### 1.1 需求名称

热门景点

### 1.2 需求定位

“热门景点”是景区旅游应用中的内容推荐能力，用于向游客优先展示景区内最具代表性、最值得优先游览或最适合当前时段浏览的景点，帮助用户快速建立游览认知，并缩短从进入应用到进入景点详情的决策路径。

该需求可作为独立内容模块存在，首页只是当前主要承载位置之一。

### 1.3 需求目标

- 提升重点景点曝光效率
- 降低用户选择成本
- 为景点详情页导流
- 承接景区讲解、导航等后续转化行为

## 2. 背景与价值

游客进入景区服务后，通常会面临“景点很多，不知道先看什么”的问题。若缺少明确推荐，用户需要自行浏览全量景点，容易造成决策迟滞，影响首屏体验和后续转化。

“热门景点”需求的价值主要体现在：

- 对游客：快速获得景区代表性景点推荐，减少搜索和判断成本
- 对景区：集中展示核心景点，提高重点内容触达率
- 对产品：形成“推荐曝光 - 详情浏览 - 讲解/导航转化”的清晰路径

## 3. 用户与场景

### 3.1 目标用户

- 首次进入景区应用的游客
- 时间有限、希望快速规划路线的游客
- 已在景区内，希望直接查看某个重点景点信息的游客

### 3.2 核心使用场景

- 用户刚进入应用，希望快速了解哪些景点值得优先看
- 用户浏览推荐内容后，希望进入详情进一步了解景点介绍
- 用户在详情页中继续使用语音讲解、地图导航等能力
- 用户觉得推荐不够，继续查看全部景点列表进行筛选

## 4. 需求范围

本需求包含以下功能范围：

- 热门景点推荐模块展示
- 热门景点列表浏览
- 热门景点详情承接
- “更多”进入景点列表页
- 详情页的讲解、图片查看、导航承接能力

本需求当前不包含：

- 收藏
- 点赞
- 评论
- 个性化推荐
- 热度解释说明
- 运营后台配置页面

## 5. 主要功能

### 5.1 热门景点模块展示

系统需提供热门景点推荐区，当前展示方式为横向景点卡片流。

模块基础组成包括：

- 模块标题
- 更多入口
- 热门景点卡片列表

当前卡片最小展示信息包括：

- 景点主图
- 景点名称

### 5.2 热门景点推荐逻辑

系统需支持识别哪些景点属于“热门景点”，并用于推荐展示。

当前实现逻辑为：

- 先获取全量景点列表
- 根据景点字段 `isHot === 1` 过滤出热门景点
- 将过滤后的结果作为热门景点列表进行渲染

这意味着当前版本的热门景点属于“规则型推荐”，而不是个性化推荐。

### 5.3 热门景点浏览

用户可在模块内左右滑动浏览多个热门景点卡片。

浏览要求：

- 卡片之间需有明确区隔
- 滑动过程应流畅
- 用户无需进入二级页面即可快速完成多景点扫读

### 5.4 进入景点详情

用户点击某个热门景点卡片后，应直接进入景点详情页。

详情页当前承接的信息包括：

- 景点名称
- 景点头图
- 景点简介
- 景点标签
- 景点地址
- 景点介绍正文
- 景点图片列表

详情页当前承接的动作包括：

- 语音讲解
- 地图导航
- 查看更多图片

### 5.5 查看更多景点

用户点击“更多”后，应进入景点列表页。

景点列表页当前承接能力包括：

- 展示全量景点
- 浏览景点名称、标签和图片
- 点击景点进入详情页

## 6. 交互流程

### 6.1 主流程

1. 用户进入承载热门景点的页面。
2. 系统加载热门景点数据。
3. 页面渲染热门景点模块。
4. 用户浏览热门景点卡片。
5. 用户可选择：
   - 点击景点卡片进入详情页
   - 点击“更多”进入景点列表页
6. 用户在详情页中继续了解景点并执行讲解或导航动作。

### 6.2 页面流转

```text
热门景点模块
  -> 点击景点卡片
     -> 景点详情页
  -> 点击“更多”
     -> 景点列表页
        -> 点击某个景点
           -> 景点详情页
```

### 6.3 数据流转

```text
获取景点列表
  -> 筛选 isHot === 1
  -> 生成热门景点列表
  -> 渲染热门景点卡片

点击景点卡片
  -> 获取景点详情
  -> 渲染详情页
```

## 7. 功能要求

### 7.1 展示要求

- 系统必须展示热门景点模块标题
- 系统必须展示热门景点列表
- 系统必须提供“更多”入口
- 系统必须支持横向滑动浏览
- 每个热门景点卡片至少展示主图和名称

### 7.2 跳转要求

- 点击热门景点卡片必须可进入景点详情页
- 点击“更多”必须进入景点列表页
- 列表页点击任一景点必须进入景点详情页

### 7.3 详情承接要求

- 景点详情页必须展示基础介绍信息
- 景点详情页必须支持图片查看
- 景点详情页必须支持语音讲解
- 景点详情页必须支持地图导航

### 7.4 数据要求

- 热门景点数据必须来源于景点数据集
- 景点数据必须包含景点标识、名称、主图等基础字段
- 当前版本必须支持通过 `isHot` 字段识别热门景点

## 8. 当前实现方案

### 8.1 承载方式

当前版本中，热门景点作为一个独立内容模块，展示在首页内容流中，与热门游记并列。

### 8.2 数据方案

当前版本涉及以下数据能力：

- 首页聚合信息接口
- 景点列表接口
- 景点详情接口

其中，热门景点当前实际采用的方案是：

- 从景点列表接口获取全量景点
- 在客户端按 `isHot === 1` 过滤
- 生成热门景点展示数据

虽然首页聚合信息中存在 `hotAttractions` 字段，但当前热门景点模块未直接使用该字段作为渲染源。

### 8.3 状态管理方案

当前列表型数据采用 `LazyDataSource` 承载，便于：

- 支持列表渲染
- 支持数据刷新
- 与横向列表组件配合使用

完整景点数据会被缓存，用于其他场景复用，例如导览等相关能力。

## 9. 技术选型

### 9.1 前端技术

当前基于 HarmonyOS ArkUI / ArkTS 实现，主要原因如下：

- 适合构建页面化、组件化的移动端体验
- 能较自然地完成列表、滚动、路由与状态响应
- 便于复用已有标题栏、轮播图、语音播报等公共组件

### 9.2 路由方式

当前采用 `NavDestination` 与 `NavPathStack` 管理页面跳转。

适用原因：

- 热门景点存在“模块 -> 列表 -> 详情”的多级跳转关系
- 详情页需要通过参数接收景点 ID
- 页面返回路径清晰，适合移动端分层浏览

### 9.3 数据组织方式

当前采用“接口响应模型 -> 页面模型映射 -> 列表数据源渲染”的方式。

适用原因：

- 有利于解耦网络结构与页面结构
- 方便后续调整展示字段
- 便于同一景点数据被多个模块复用

### 9.4 景点详情页技术约束

景点详情页中的“语音讲解”和“景点导航”属于依赖系统能力的功能点，期望技术实现可简化为以下两项：

#### 9.4.1 语音讲解技术约束

- 期望依赖 `@kit.SpeechKit` 的 `TextReader` 能力实现景点介绍播报
- 页面层通过语音讲解组件承接播报入口，景点详情页需提供可播报的介绍文案

#### 9.4.2 景点导航技术约束

- 期望依赖 `@kit.AbilityKit` 的 `Want` 与 `startAbility` 能力拉起地图应用进行导航
- 景点详情页需提供目标景点的经纬度和名称，作为地图导航的入参

## 10. UX 原型设计

### 10.1 热门景点模块原型

```text
┌──────────────────────────────┐
│ 热门景点                  更多 > │
├──────────────────────────────┤
│ [景点卡1]  [景点卡2]  [景点卡3] │
│ [图片+名称] [图片+名称] [图片+名称]│
└──────────────────────────────┘
```

交互说明：

- 左右滑动浏览更多热门景点
- 点击卡片进入景点详情
- 点击“更多”进入景点列表

### 10.2 景点列表页原型

```text
┌──────────────────────────────┐
│ < 返回        景点列表         │
├──────────────────────────────┤
│ [顶部轮播 Banner]             │
├──────────────────────────────┤
│ [封面] 名称                   │
│        标签 标签              │
│        缩略图 缩略图 缩略图    │
├──────────────────────────────┤
│ [封面] 名称                   │
│        标签 标签              │
│        缩略图 缩略图 缩略图    │
└──────────────────────────────┘
```

### 10.3 景点详情页原型

```text
┌──────────────────────────────┐
│ < 返回       景点名称          │
├──────────────────────────────┤
│ [景点主图]  名称 + 简介        │
│           标签 标签    [语音]  │
├──────────────────────────────┤
│ 开放信息 / 景点地址    [导航]  │
├──────────────────────────────┤
│ 景点介绍                        │
│ 景点介绍正文                    │
├──────────────────────────────┤
│ 图片/视频                查看全部│
│ [图] [图] [图]                  │
└──────────────────────────────┘
```

### 10.4 UX 设计原则

该需求当前遵循以下体验原则：

- 首屏快速识别：用户一眼能看出这是重点推荐景点
- 操作路径简短：从推荐到详情尽量减少跳转成本
- 信息层级清晰：首页轻量展示，详情页深度承接
- 动作闭环完整：详情页可继续讲解和导航，不中断用户意图

## 11. 非功能要求

- 列表滑动应保持流畅
- 图片展示应稳定，不应出现明显布局抖动
- 页面跳转应具备明确返回路径
- 当热门景点数量较少时，模块仍应正常展示

## 12. 后续优化方向

后续若将热门景点升级为重点运营能力，建议考虑：

- 使用统一聚合接口直接下发热门景点
- 增加空状态、异常状态和加载状态
- 增加标签、简介、热度等更完整的卡片信息
- 增加曝光、点击、详情转化等埋点统计
- 增加运营排序和节假日专题推荐能力
- 引入位置、时间或人群维度的动态推荐策略
