## 页面结构

### 主入口与导航（底部 TabBar，固定四个标签）

| 入口/导航 | 对应页面 | 来源 | 说明 |

| 首页 | 首页 | PRD | 轮播展示、公告信息、服务导航（文旅商城/票务预订/餐饮住宿/游览线路）、热门景点、攻略游记 |

## UI 元素匹配优先级

1. 用户可见中文文本
2. 用户可见英文文本
3. 图标含义或区域位置
4. 可访问性文本 / Key（仅在可见文本缺失时使用）

## 导航约定

- **返回上一级**: 优先使用页面顶部左上角返回箭头按钮；若无返回控件，使用系统返回键
- **页面跳转**: 点击明确入口后等待目标页面标题、核心内容或弹窗出现
- **主导航切换**: 通过底部 TabBar 切换：【首页】、【门票】、【导览】、【我的】
- **跨应用跳转**: 仅验证目标系统界面已弹出或加载，不继续验证外部应用深层流程

### 通用适配巡检规则

所有断点下均需观察：

- 页面核心区域完整可见，无空白首屏、内容丢失或布局塌陷
- 无异常横向溢出、非预期横向滚动或内容超出屏幕边界
- 无元素重叠、关键内容遮挡、弹窗/键盘/导航遮挡主操作按钮
- 标题、按钮、表单字段、导航项等关键文本可读，无明显截断或压缩到不可识别
- 图片、Banner、卡片封面比例正常，无明显拉伸、压扁或核心内容裁切
- 关键交互入口可见且可点击

## 测试数据与 fixture 边界

- 应用卡片只描述稳定 UI 结构、导航入口和元素命名，不自动证明测试环境存在某类业务数据
- 只有 PRD、用户输入或 fixture 文档明确说明时，才可声明账号已登录、存在指定记录、存在默认数据、列表为空、订单处于某状态等
- 若没有明确 fixture，生成 JSON 用例时不要依赖指定业务状态、真实支付结果、退款状态、通知送达、日历写入成功或空数据列表
- 列表、横向卡片、瀑布流、分页加载等数据规模型能力，只有明确 fixture 保证条目数量时，才可验证"滑动后展示更多"；否则只验证当前可见结构
