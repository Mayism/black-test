## L0 用例 - 核心烟测

### MUST-01 首页TabBar与轮播展示

| 项目 | 内容 |
|------|------|
| **等级** | L0 |
| **前置条件** | 应用已启动并停留在【首页】；网络连接正常 |
| **覆盖模块** | 首页 - TabBar、轮播图、服务导航 |

| 步骤 | 操作 | 检查点 |
|------|------|--------|
| 1 | 确认底部TabBar显示【首页】、【门票】、【导览】、【我的】四个标签，【首页】标签处于高亮选中状态 | 底部TabBar完整可见，【首页】标签高亮选中，【门票】、【导览】、【我的】标签可见 |
| 2 | 查看页面上方轮播图区域 | 页面顶部可见轮播图区域，展示景区宣传图片，轮播指示器可见 |
| 3 | 查看轮播图下方的服务导航模块 | 页面可见服务导航网格区域，包含【文旅商城】、【票务预订】、【餐饮住宿】、【游览线路】等图标入口 |

**预期结果**：首页完整展示底部TabBar（首页高亮）、顶部轮播图区和下方服务导航入口模块，页面不空白

## 不适合黑盒自动化的场景

以下场景因依赖真实支付、后端数据、跨应用能力或 fixture 缺失，不纳入本次 JSON 自动化用例：

| 场景 | 排除原因 | 建议处理 |
|------|----------|----------|
| 门票预订完整流程（选择日期/数量/旅客 → 确认订单 → 支付） | 需要账号已关联、存在常用旅客、真实支付 | 需要 fixture：测试环境预置已关联账号和常用旅客数据，且提供 mock 支付通道 |
| 取消订单 | 需要存在指定状态订单（待支付/已支付），属于 fixture 场景 | 需要 fixture |
| 订单列表及订单详情 | 需要存在至少一条历史订单 | 需要 fixture |
| 景点导航（跨应用跳转地图） | 跨应用操作不可控，仅验证跳转行为，不作为独立用例 | 可在导览相关用例中附带验证，但导航到地图后的行为属于地图应用内部 |
| 语音播报播放控制 | 涉及音频播放、网络音频流、媒体控制组件 | 需要 fixture：确保音频资源可用且测试环境支持音频输出 |
| 景点实况（人流/排队/开放状态） | 需要后端实时数据模拟，纯前端无法判定 | 需要 fixture：mock 实时数据服务 |
| 攻略游记搜索 | 需要搜索功能独立页面和搜索 API | 需要 fixture：确保搜索 API 可用 |
| 首页公告信息详情 | 公告详情页依赖公告数据 | 如果首页可见公告条目，可点击验证详情；若无数据则不生成 |
| 旅客管理增删改 | 删除依赖已有旅客数据，编辑依赖可编辑条目 | 需要 fixture：游客列表预置至少1条可编辑/可删除旅客 |
| 地址管理增删改 | 删除依赖已有地址数据 | 需要 fixture：地址列表预置至少1条地址 |
| 全部页面空状态验证 | 需要所有列表均为空（需要清库或空数据 mock） | 需要 fixture：mock 空数据环境 |
| 权限拒绝后功能降级 | 需要权限被主动拒绝，且验证对应功能是否降级 | 需要 fixture：明确权限被拒绝后的功能降级策略 |

## 执行注意事项

1. 所有用例均可独立运行，无需特定执行顺序
2. L0 用例优先执行，覆盖 4 个 Tab 的基本可达性
3. 导览相关用例可能触发位置权限弹窗，Agent 应按步骤要求处理
4. 账号关联校验用例（SHOULD-04）包含条件分支，Agent 应根据实际 UI 状态选择对应路径
5. 列表/卡片类检查点默认只验证当前可见结构，不要求特定数量
