## 详情

### C-A01 活动Tab页面结构展示

- **等级**: L0
- **前置条件**: 应用已启动并停留在首页【推荐】Tab；网络连接正常；mock数据包含活动列表数据
- **步骤**:
  1. 点击顶部Tab栏中的【活动】 → 页面切换到【活动】Tab，顶部显示城市选择器（含定位图标、【活动地区】标签和当前城市名称），下方显示活动卡片列表
  2. 观察活动卡片的结构 → 活动卡片包含活动主图，图片上叠加日期（如01-15）、活动名称（如高尔夫联谊-南京专场）等文字信息，底部展示副标题、时间范围和男女比例
  3. 向下滑动活动列表到底部 → 列表下方出现【往期活动】分区标题，下方展示已结束活动的卡片，卡片上叠加【已结束】或类似状态标签
- **预期结果**: 活动Tab展示城市选择器、未来活动列表和往期活动分区，活动卡片包含主图、名称、时间、男女比例等完整信息

### C-A02 活动列表-城市筛选切换

- **等级**: L0
- **前置条件**: 应用已启动并停留在首页【推荐】Tab；网络连接正常；mock数据包含多城市活动数据
- **步骤**:
  1. 点击顶部Tab栏中的【活动】 → 页面切换到【活动】Tab，城市选择器显示当前城市名称
  2. 点击城市选择器（城市名称及下拉箭头区域） → 弹出城市列表或跳转到城市选择页，显示可选城市（如北京、上海、广州、南京、西安、杭州等）
  3. 在可选城市中点击一个不同于当前显示的城市 → 页面返回【活动】Tab，城市选择器上的城市名称更新为所选城市
  4. 等待 1 秒让活动列表刷新 → 活动列表内容已刷新，卡片中的城市专场标识或地址信息与所选城市一致
- **预期结果**: 切换城市后，活动列表按所选城市筛选刷新，城市名称更新，活动卡片信息与新城市一致

### C-A03 活动详情查看

- **等级**: L0
- **前置条件**: 应用已启动并停留在首页【推荐】Tab；网络连接正常
- **步骤**:
  1. 点击顶部Tab栏中的【活动】 → 页面切换到【活动】Tab，展示活动列表
  2. 点击未来活动区域第一个活动卡片 → 页面跳转到活动详情页，顶部显示返回按钮和【活动详情】标题
  3. 观察活动详情页上半部分 → 页面展示活动主图（大图封面覆盖宽度），下方显示信息卡片区域
  4. 向下滑动详情页 → 信息卡片依次展示活动名称（含标题图标）、地点（含地点图标）、时间范围（含时间图标）、备注说明（含备注图标）；下方显示Swiper图片轮播区域，含多张详情图和圆点指示器
  5. 观察页面底部按钮区域 → 底部固定显示按钮区域，文案为【¥XXX 立即报名】或【活动已报满，请看看其他活动吧】，或者已结束则不展示按钮
- **预期结果**: 活动详情页正确展示主图封面、活动信息卡片（名称/地点/时间/备注）、Swiper轮播图和底部状态相关按钮区域

### C-A06 我的订单页-页面结构展示

- **等级**: L0
- **前置条件**: 应用已启动并停留在首页；网络连接正常；mock数据包含已报名活动记录
- **步骤**:
  1. 切换到【我的】页面（通过底部标签或导航入口） → 页面切换到【我的】页
  2. 在【我的】页面中点击【我的订单】入口 → 页面跳转到【我的订单】页，顶部显示返回按钮和【我的订单】标题
  3. 观察订单列表区域 → 页面展示活动订单卡片列表，每张卡片包含左侧活动图片（方形圆角）、右侧活动名称（含图标）、时间（含图标）、地点（含图标）信息，卡片底部右侧显示状态标签（如【已报名】【待付款】【已结束】【已取消】）
  4. 观察状态标签的样式 → 状态标签为圆角按钮样式，不同状态展示不同颜色和文案【待付款】【已报名】【已结束】【已取消】

- **等级**: L1
- **前置条件**: 应用已启动并停留在首页【推荐】Tab；网络连接正常；mock数据包含已报满的活动
- **步骤**:

> **注**: 若未来活动区域无已报满活动，Agent 应调用 `complete(success=false, message="FIXTURE_MISSING: mock数据中无已报满活动，无法验证")`。

- **等级**: L1
- **前置条件**: 应用已启动并停留在首页【推荐】Tab；网络连接正常；mock数据包含可报名的未开始活动

## 执行说明

- 所有用例独立运行，可从首页【推荐】Tab 或【活动】Tab 进入
- mock数据中含活动列表、城市数据、已报名订单数据，部分用例（C-A11）依赖特定活动状态（已报满）
- 活动列表页顶部Tab栏结构：【筛选图标】 推荐 | 活动，点击【活动】切换
- 若 mock 数据中未来活动第一个卡片恰为已报满，C-A04 会失败（期望立即报名但实际为已报满），这是预期行为，执行时需根据实际mock数据调整
