# droidrun Agent 行为约束（rentandbuy 测试阶段）

本测试套件属于 **rentandbuy（租房找房）** 的一多适配基线巡检阶段，目标是在不同横断点下探索可达页面，验证通用适配规则是否满足。

## 执行原则

- 按 `test_steps` 顺序执行，不跳步、不合并步骤。
- 若某个 action 写有「如……则跳过本步骤」，先观察当前 UI 状态：满足跳过条件时不执行该 action，直接按下一个 step 继续。
- 每步之后验证对应 checkpoint。checkpoint 字面要求要对齐：写「页面无明显横向溢出」就要观察页面内容是否超出屏幕边界；写「主操作入口未被遮挡」就要确认入口按钮完整可见且可点击。
- **禁止启发式降级**：「看起来像对」、「差不多满足」、「应用没崩溃就算成功」都不算 pass。
- 只执行步骤里明确要求的动作，不要自行探索 UI。
- 每步之间给 UI 一点时间稳定（常规 0.5~1s；网络加载等慢操作 2~5s）。
- 同一元素/同一路径连续失败 2 次后，不要继续重复点击；改用替代入口、返回上一级，或调用 `complete(success=false)` 给出具体失败原因。
- 同一入口点击后页面没有变化，先检查是否有授权/账号/mock 弹窗遮挡；若有明确正向按钮（如【允许】、【确定】、【确认授权】），按用例目标点击处理。处理后仍未到达目标页，不要继续等待。
- 如果已经能判断 checkpoint 或 expected_result 不满足，应尽快 `complete(success=false)`；不要为了「修复」业务状态继续执行与步骤无关的探索。
- 到达最后一个 checkpoint 且 expected_result 已满足时，必须立即 `complete(success=true)`，禁止继续点击、滑动或探索。
- 如果页面已经偏离当前步骤目标，不要返回重来；立即 `complete(success=false)` 并说明偏离位置。
- 在 final-chance 或工具只允许 `complete` 的回合，必须调用 `complete`；不得输出 `click`、`swipe`、`type`、`open_app` 等动作。

## 查找与滚动纪律

- 禁止在长列表中无限查找。最多尝试 1 次滚动；仍找不到目标就 `complete(success=false)`。
- 列表、横向卡片、瀑布流的 mock 数据可能较少；若当前可见条目结构已满足，不要反复滑动。按用例要求调用 `complete(success=true)`。
- 若 `preconditions` 明确要求「不少于 N 个条目/卡片」，而当前 UI 验证不足 N 个，应快速 `complete(success=false, message="FIXTURE_MISSING: 缺少足量列表/卡片数据")`，不要继续探索。

## Preconditions 判定纪律

`preconditions` 只用于建立或确认起始状态，不是隐藏的完整测试流程。

如果前置条件依赖当前 UI 无法稳定创建的数据或环境状态，且当前页面无法在 2-3 步内稳定确认或到达，则立即结束当前 phase：

```text
complete(success=false, message="FIXTURE_MISSING: 缺少……前置数据/环境，无法通过 UI 稳定建立")
```

不要循环点击、不要反复打开同一页面、不要把前置条件失败伪装成业务功能失败。

## 权限弹窗

- 位置权限弹窗：默认点【允许】。
- 电话权限弹窗：根据用例说明处理。
- 存储权限弹窗：默认点【允许】。
- 通知权限弹窗：默认点【允许】。
- 除非 `preconditions` 明确要求拒绝，遇到系统权限弹窗默认点【允许】，然后等 1~2s 让权限生效。

## 失败现场

失败时把下列信息写进 trajectory：当前页面 UI tree、最后一次截图、失败步骤编号与具体原因（元素未找到 / 文本不匹配 / 超时 / 异常）。

## 基础设施错误分流（AAMS / uitest）

如果日志或执行反馈里出现以下任一关键词：
- `Can not connect to AAMS`
- `REGISTER_LISTENER_FAILED`
- `RET_TIMEOUT`
- `REGISTER_LIST_REGISTERED`
- `State retrieval failing, attempting recovery`

按**基础设施故障**处理，不要把它判定为业务功能失败，也不要放宽 checkpoint。

处理方式：
- 立即结束当前用例并返回失败，`message` 必须包含前缀 `INFRA_AAMS` 与命中的关键词，便于上游 agent 触发自动恢复重跑。
- 不要自行给出「功能已通过」的结论。
- 不要求你执行设备重启/重置类动作。

## 应用约定（rentandbuy）

PRD 仅含标题「租房找房应用一多适配」，以下为租房找房应用的通用 UI 约定；具体页面和标签名称以应用实际 UI 为准。

- 启动后默认进入首屏页面，底部可能有固定标签（如【首页】、【找房】、【消息】、【我的】）。
- 底部标签固定展示，**不允许横向滑动切换**。
- 页面导航（推测）：
  - 首页 → 城市选择页（点击城市名称）
  - 首页 → 搜索页（点击搜索框）
  - 首页/找房 → 房源详情页（点击房源卡片）
- 返回上一级：顶部左上角返回箭头。
- UI 元素用 `【XX】` 标注，优先按**中文 label** 匹配。

## rentandbuy 特有注意事项

### 一多适配基线巡检

本套件为基线巡检类型，不要求验证具体页面布局规则或定制断点逻辑。巡检要点：

1. 在每个横向断点（sm/md/lg）下启动应用
2. 观察首屏是否有空白首屏、横向溢出、遮挡、重叠、关键文字截断或图片比例异常
3. 依次进入可达子页面（最多 2 个入口）并观察通用布局无问题
4. 检查详情页或列表项内容完整可见
5. 结果只说明「当前可达页面未发现明显适配问题」，不证明全量页面覆盖

### 通用适配检查项

- 页面核心区域完整可见，无空白首屏、内容丢失或布局塌陷
- 无异常横向溢出、非预期横向滚动或内容超出屏幕边界
- 无元素重叠、关键内容遮挡、弹窗/键盘/导航遮挡主操作按钮
- 标题、价格、按钮、表单字段、导航项等关键文本可读，无明显截断或压缩
- 图片、Banner、卡片封面比例正常，无明显拉伸、压扁或核心内容被裁切
- 导航、列表项、按钮、输入框等关键交互入口可见且可点击
- 滚动区域边界清晰，固定导航/底部按钮不与内容区域冲突

### 断点说明

| 断点 | 窗口宽度 (vp) | 典型形态 |
|------|--------------|---------|
| sm | [320, 600) | 手机竖屏、部分折叠外屏 |
| md | [600, 840) | 部分折叠内屏、分屏窗口 |
| lg | [840, 1440) | 平板横屏、三折展开态 |

断点条件由测试框架或设备形态保证，Agent 直接验证当前窗口下的布局表现。若当前窗口宽度不在目标断点范围，立即 `complete(success=false, message="BREAKPOINT_MISMATCH: 当前窗口宽度不在目标断点范围")`。

### 慢操作等待

- 城市切换后列表刷新：等待 ≥1s 再验证
- 搜索操作：点击搜索按钮后等待 ≥1s 再验证结果列表
- 筛选条件变更：等待 ≥1s 再验证筛选结果
- 首次启动/冷启动：等待 ≥2s 再验证首页内容

### Mock 数据

- 当前测试环境可能使用 mock 数据，房源名称、价格、户型等信息可能为固定值。
- checkpoint 应关注 UI 状态而非具体数据值是否匹配线上。
- 不要因 mock 数据差异判定布局适配失败。
